1. System Overview — Eight GPUs, Two Pools, One Router

Concurrency: the four standalone GPUs generate while the four trainer GPUs update FSDP2. When the queue is short and the estimated saved wait exceeds transition cost, the trainer pool temporarily contributes four more vLLM replicas; it never trains and generates simultaneously on those same GPUs.

3. Streaming Dataflow — 64 Prompt Groups, 16 Samples + One Baseline Each

The scheduling unit is a prompt group, not one trajectory. A training batch selects 64 prompt UUIDs and materializes all successful trajectories under each UUID. ReMax’s greedy baseline trajectory is read for its reward, copied into reward_baselines, then cleared rather than trained as a sampled response.

4. Per-Step Control — Adaptive Lending with a Cost Gate

Effective threshold, not nominal ratio: round(0.4 × 64)=26, but _switch_threshold() floors this at one mini-batch, 64 / parameter_sync_step = 64. Because parameter_sync_step=1, all adaptive ratios map to the same 64-group threshold. Adaptation still logs ratio changes, but cannot alter reclamation depth for this experiment.

6. Partial Rollout — Hybrid Interruption Is a Resume Boundary

Only hybrid requests are aborted during reclamation; dedicated replicas continue serving. The fully async client treats an abort as a retry boundary and preserves the cumulative token limit. A response may therefore span policy versions, which is why queue tags record both min_global_steps and max_global_steps.

7. Parameter Synchronization — One Mandatory Path, One Conditional Path

Why two paths: dedicated rollout processes require a real inter-pool transport and are refreshed every step. Hybrid replicas share the actor worker group, so a direct naive update suffices—and is skipped whenever the cost gate leaves those GPUs in TRAINER mode. With model.lora.merge=true, the synchronized representation is merged/full weights rather than adapter-only fast sync.

8. Backpressure, Staleness, and Operating Modes

Queue backpressure 2 s polling

  • wait_for_sampleable(64) blocks the controller, not generation actors.
  • Oldest prompt versions are selected first.
  • Evicted async groups trigger one-for-one prompt refill.

Freshness budget drop

  • A terminal group is stale when step − prompt_step + 1 > 8.
  • Stale groups are cleared and replaced before selection.
  • Partial trajectories expose version span separately via min/max versions.

Capacity decision 4 ↔ 8 rollout GPUs

  • Standalone capacity remains four GPUs.
  • Lending doubles rollout GPUs, so the fixed scaling factor is 2.0.
  • Estimated benefit uses the corresponding 1 − 1/2 = 50% wait-time saving.

Switch-cost memory window=3

  • Tracks complete ROLLOUT→TRAINER and TRAINER→ROLLOUT costs.
  • Only lends if shortage exists and benefit is unknown or exceeds measured cost.
  • Final step never lends the trainer pool again.
