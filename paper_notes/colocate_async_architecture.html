1. System Overview — One Pool, Two Alternating Personalities

The central idea: colocation removes a dedicated rollout pool, but prevents simultaneous rollout and training on the shared GPUs. Asynchrony is expressed as queued prompt work, background AgentLoop tasks, and resumable trajectories across repeated GPU mode switches.

Pipeline seed controller

on_train_begin() submits num_warmup_batches before step 1. This reduces the first empty-buffer wait; checkpoint recovery reissues pending/running prompts before adding new warmup work.

3. Streaming Dataflow — Prompt Groups Through TransferQueue

The scheduling unit is a prompt group (important for GRPO); materialization returns all trajectory keys belonging to selected prompt UUIDs. Generation writes results independently of the trainer’s blocking sampler.

4. Per-Step Runtime — Generate, Freeze, Train, Refresh, Resume

No same-GPU compute overlap: the rollout and training phases time-share one pool. The gain comes from preserving unfinished work, keeping prompt/agent state asynchronous, reducing discarded long responses, and immediately resuming generation after each update.

A · Fill / wait GPU rollout

  • prepare_step() adds one full training batch.
  • ReplayBufferAsync.sample() waits for enough terminal groups.
  • Warmup work and refills keep the queue supplied.

B · Quiesce transition

  • abort_replicas() terminates active server calls.
  • Clients retain partial tokens and log-probs.
  • sleep_replicas() releases weights and KV cache.

C · PPO pipeline GPU trainer

colocated reward (optional) balance DP batch old log-prob → ref / value (optional) advantage → critic (optional) → actor update

D · Refresh / resume naive sync

  • Restore rollout weight memory.
  • Export model-engine tensors and update rollout.
  • Restore KV cache; resume partial requests under the new version.

5. Partial Rollout — Interruption Becomes a Retry Boundary

A resumed trajectory can span multiple policy versions. The client records min_global_steps and max_global_steps; the retained prefix is re-prefilled because sleeping discarded its KV cache.

6. Parameter Synchronization — Naive Colocated Path

Unlike separate_async, this path does not construct an inter-pool NCCL/NIXL topology: setup forcibly selects backend=naive because actor and rollout inhabit the same worker processes.

7. Backpressure, Freshness, and Failure Recovery

Polling backpressure ReplayBufferAsync

  • Sampler polls queue metadata every 2.0 s.
  • Training waits until train_batch_size prompt groups are eligible.
  • Oldest prompt versions are selected first.

Drop strategy default

  • Terminal group age beyond threshold → evict.
  • DAPO-filtered and failed groups join the same eviction union.
  • Exactly one replacement prompt is dispatched per evicted async group.

Wait strategy dropless

  • Do not evict for staleness.
  • If any in-flight group reaches threshold, block sampling until it finishes.
  • Failure and DAPO rejection still refill.

Checkpoint recovery durable prompts

  • Finished trajectories restore as-is.
  • Pending/running groups have consumed dataloader entries.
  • Saved prompt fields are reissued rather than silently lost.

Three distinct version signals
