1. System Overview — Two GPU Pools, One On-Policy Loop

Separation of concerns: the student generates on-policy responses and is updated; teachers only evaluate those completed responses. Teacher replicas live in a dedicated pool, load once, and never receive student weight updates.

2. Bootstrap — Validate, Partition, Launch, Wire

Sizing invariant config validation

teacher_pool_size = n_gpus_per_node × nnodes per_replica = TP × DP × PP Σ(num_replicas × per_replica) == teacher_pool_size

Single-teacher mode derives num_replicas automatically. Multi-teacher mode requires each explicit footprint to sum exactly to the pool.

Replica placement Ray placement groups

MultiTeacherModelManager first partitions the combined teacher pool by teacher, then TeacherModelManager partitions each sub-pool by replica. Node-span validation rejects a linear split that unexpectedly straddles extra nodes.

3. Streaming Dataflow — Score Each Sample as Soon as It Finishes

S = prompt length + response length. For estimator losses, K=1 and only the sampled token's teacher log-probability is needed. For forward_kl_topk, K is the configured top-K width.

4. Concurrency, Routing, and Backpressure

Natural concurrency asyncio + Ray

  • Each sample has its own agent-loop coroutine.
  • One teacher request begins immediately after that sample finishes.
  • A per-teacher load balancer chooses the least-loaded active replica.

Backpressure boundary teacher server

  • No separate client-side rate limiter or retry queue.
  • vLLM/SGLang internal batching absorbs concurrent calls.
  • max_num_seqs bounds server-side concurrent sequences.

Failure semantics fail closed

  • Unknown multi-teacher routing keys raise immediately.
  • No available server raises from the load balancer.
  • Inference exceptions propagate; failed prompt groups are not trained.

Why temperature is 1.0 request construction

The teacher performs a forward pass over existing student tokens via prompt_logprobs; it does not sample those tokens. The manager therefore forces temperature=1.0 and warns if configuration says otherwise.

5. Student Optimization — Dual-Purpose Loss Function

The selected lines in distillation_ppo_loss() describe two calls, not two losses. The first call exists only for top-K mode while full logits are resident. The second call always constructs the final scalar objective after forward outputs are prepared.

Direct GKD-style OPD use_policy_gradient=false

d_t = registered_distillation_loss(...) L_D = aggregate(d_t, response_mask) backpropagate L_D directly

Recommended for k3 or forward_kl_topk. Full top-K distributional gradients remain useful.

Policy-gradient OPD use_policy_gradient=true

advantage_t = -stop_gradient(d_t) L_D = PPOClip(logπθ, logπold, advantage_t) backpropagate through sampled logπθ

Recommended with k1. Clipping uses the distillation loss configuration's vanilla policy-loss settings.

Final objective

Lfinal = 𝟙[use_task_rewards] · Ltask-PPO + cD · Ldistill

When task rewards are disabled, the implementation uses coefficient 1 for the distillation-only objective. When enabled, distillation_loss_coef controls the mixture.

7. Parameter Synchronization — Student Changes, Teacher Does Not

OPD adds no teacher synchronization protocol. Existing trainer machinery refreshes the student rollout policy after actor updates. Teacher model weights remain frozen for the full run, preserving a stable target distribution.

Teacher teacher_pool

model_path = Qwen/Qwen3-32B n_gpus_per_node = 4 nnodes = 1 inference.name = vllm inference.tensor_model_parallel_size = 2 ⇒ num_replicas = 4 / 2 = 2

Distillation objective example default

enabled = true loss_mode = k1 use_policy_gradient = true use_task_rewards = false loss_max_clamp = 10.0 log_prob_min_clamp = -10.0

This is pure PG-OPD: negative k1 is used as a detached advantage, with no task-reward loss.

Batch and context controller

train_batch_size = 128 ppo_mini_batch_size = 128 max_prompt_length = 1024 max_response_length = 2048 teacher context requirement = 3073

The extra token is required because teacher requests use max_tokens=1 while requesting prompt log-probabilities.
