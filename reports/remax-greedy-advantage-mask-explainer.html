01 / Separate two questions

How good is this response?

Score both the sample and the greedy result with the existing ASR reward function. Ground truth still supplies the reference for char/word accuracy; the other components check language and output quality.

The combined reward includes char, word, language, format, and bracket scores.

Where should that comparison act?

Align the sampled and greedy token IDs. Zero policy advantages on their matching spans. Keep the advantage on sampled insertions, replacements, and selected boundaries for omitted greedy tokens.

Ground truth determines quality, but it does not determine this mask.

A = R(sample) - R(greedy)

Apolicy,t = Aexisting,t × Mt

Mt = 1 for a selected valid sampled token; otherwise 0.

The first formula describes the reference recipe's scalar ReMax advantage. If advantage normalization, sign-only conversion, or scaling is enabled, compute those first, then apply the mask.

1. ScoreGenerate a sample and a greedy result for the same prompt. Compute their rewards.
2. AlignFind matching token blocks and the sampled tokens where the responses differ.
3. MaskMultiply final advantages by the mask. Send them to the existing token-level policy loss.

Why does a deletion need a boundary token?

An omitted greedy token has no sampled log probability to update. We therefore select the next valid sampled token, even if it matches greedy. For an omitted tail, select EOS when present. If a truncated response has no following token, select its last valid token. An empty sampled response has nothing to select. Padding is never selected.

This is a credit-assignment heuristic, not a direct gradient on the missing token. When a replacement has more greedy tokens than sampled tokens, also anchor the excess greedy suffix at the next sampled token.

03 / Mask the advantage, not the response

The reward manager still places the scalar score at the final valid response token. ReMax still broadcasts the resulting outcome advantage. The new mask is applied after advantage calculation, not to the reward tensor.

L_policy = sum_t [valid_t * PPO_loss(ratio_t, A_existing,t * M_t)]
           / sum_t valid_t

L_total  = L_policy + beta_KL * KL_full_response
                     - beta_entropy * entropy_full_response

There is no division by the mismatch count and no redistribution of credit. For example, with four valid tokens, A = +0.20 and one selected token, the mean advantage is +0.05, not +0.20. The policy update generally becomes smaller when fewer tokens are selected; actual gradients also depend on token probabilities and PPO clipping.

The reference uses actor KL coefficient 0.001 and entropy coefficient 0. Matching tokens have no direct policy-loss term, but shared model parameters, context, and KL can still change their probabilities.

04 / Useful intuition, important limits

Why it might help

  • Focus reward-driven credit on choices that distinguish sampling from the greedy baseline.
  • Avoid broadcasting the same positive or negative policy credit onto every shared span.
  • Keep reference-policy regularization active throughout the response.
  • Allow an injected GT response to receive positive credit where it improves on greedy.

What it does not establish

  • This is not ground-truth error localization. A wrong token shared by sample and greedy is masked out.
  • All selected tokens receive the same sequence-level sign. A better sample can still reinforce a locally bad edit.
  • A correct shared span is not guaranteed to remain unchanged after optimization.
  • Reduced update magnitude is a confound: improvement may come from weaker updates, not better localization alone.

This changes the training objective. A response-dependent mask is a heuristic modification of ReMax's policy-gradient estimator, not a claim of unbiased per-edit credit. Lower validation p_err is an empirical goal, not a mathematical guarantee.

Alignment uses SequenceMatcher(autojunk=False) on token IDs, not minimum-Levenshtein char/word alignment. Repeated tokens and alternate tokenizations can affect which spans match. The exact greedy response used for reward scoring is also used for masking.

05 / The implementation in this recipe

algorithm:
  adv_estimator: remax
  remax_advantage_mask: true
  use_kl_in_reward: false

New opt-in recipe differs from the reference recipe only by the enabled flag after composition. It retains 8 rollouts (including one GT rollout), batch size 128, 200 steps, and the 2-node / 16-GPU topology.

The reward uses mean over five weighted components: char: 1.0, word: 1.0, lang: 0.5, fmt: 0.2, bracket: 1.0. This means a division by five, not by the sum of weights. Component clipping remains as defined by the scorer. The mask acts on this combined reward advantage.

  1. Alignment helper builds a binary mask including deletion anchors.
  2. DAPO trainer pairs each rollout with its prompt's greedy result. The mask travels with the tensor batch through filtering and reordering.
  3. Shared advantage calculation validates the mask and multiplies final advantages once. Scores, rewards, baselines, and returns stay intact.
  4. Metrics report selected-token fraction/counts, zero-mask fraction, and empty-response count on the final retained batch.

The new mode requires ReMax and vanilla token-level policy loss. Combining it with in-reward KL is rejected. Advantage masking is the only supported ReMax masking mode. Training paths that do not supply a mask fail explicitly. No extra greedy generation is needed: ReMax already produces that baseline.

Generation settings remain unchanged, including the inherited greedy validation cap of 256 tokens versus 768 for sampled responses. Differences caused by that cap also affect the mask.

06 / Judge it by validation p_err

Correctness checks

After removing the legacy loss-mask mode, the focused test run passed 94 tests and 4 subtests. Coverage includes token alignment, deletion boundaries, baseline pairing, batch propagation, exact A_new = A_old * M, regularization, and recipe parity.

These checks validate mechanics, not ASR quality.

Quality experiment

  1. Compare to step-0 validation on the same datasets.
  2. Compare masked and unmasked runs at matched steps and settings.
  3. Report per-dataset p_err, the same aggregate across runs, and regressions.
  4. Inspect mask sparsity and update magnitude alongside quality.
