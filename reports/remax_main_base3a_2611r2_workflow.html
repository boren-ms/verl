From one YAML to one gradient step: remax_main_base3a_2611r2

This page follows Base3a from launch to checkpoint. It covers how the config is built from inherited layers, how six ASR training sources become one fixed-order stream of prompts, how ReMax compares eight sampled transcripts against a greedy one, how the vote reward turns that comparison into a scalar, and how validation is scored. Every claim points to the code that implements it.

01

Launch: file name chooses the entry point

bash quick_run.sh recipe/phimm/config/v2611_dev/main/remax_main_base3a_2611r2.yaml [hydra overrides...]

quick_run.sh

  1. Splits the path into --config-dir and --config-name.
  2. Chooses a module from the name prefix: remax_* → recipe.phimm.main_asr_remax. Other prefixes: gen_, eval_, grpo_, rloo_, …
  3. Runs python3 ray_tool.py prepare_env on every Ray node.
  4. Submits with ray job submit --no-wait and passes trainer.experiment_name=<config name>. The log is tee'd to <name>.log.

main_asr_remax → main_asr_dapo.run_ppo

  1. main_asr_remax.py is a thin Hydra wrapper that calls run_ppo(config).
  2. run_ppo runs ray.init with env vars (VLLM_PLUGINS=qwen35_audio, VERL_USE_EXTERNAL_MODULES=hf_qwen35_audio, DATA_PATH is required) and starts a remote TaskRunner.
  3. TaskRunner.run resolves the config, runs copy_to_local(model.path) (az:// download), loads the tokenizer and processor, and maps the FSDP worker roles (ActorRollout, plus RefPolicy because use_kl_loss is on).
  4. It builds two reward managers: train (dapo) and val (long_audio_grouped).
  5. It creates RayDAPOTrainer with dump_fn=get_hyp_text, then calls init_workers() and fit().

Config layers: Base3a is a delta on a delta

Hydra composes from the bottom of this tree up, with later layers overriding earlier ones. Each layer adds only a small amount, so to read Base3a you have to read the whole chain.

remax_main_base3a_2611r2.yaml # model path (2611 qwen9b step 38000), 6 train sources + mix, aishell reward └─ main/base2a_smts.yaml # + val: zh_hard top500 (AISHELL-1 test, FLEURS zh) → openasr_expansion └─ main/base1a_smts.yaml # + val: OpenLong u2 cohorts (earnings21/22, coraal, e22_cleaned_aa) └─ main/base1_smts.yaml # LoRA 320, lr 6e-7 const, n=8, seq-mean-token-sum, bs 128, 2 epochs, │ # val: earnings22 verb, OpenASR-ML bad, urgent2024_delta; 'librispeech' reward └─ v2611_dev/base.yaml # ReMax, vLLM/FSDP2, KL loss, clip .2/.28, val reward fns, trainer freqs └─ /ppo_trainer # verl/trainer/config defaults
Base3a vs Base2c: the only differences (besides experiment_name) are that the openml_verb_langhint_v0 train source and its {name: openml, sample: 13169} mix entry are removed. Every validation setting is the same.

How a YAML spec becomes rows

RLHFDataset.__init__ flattens data.train_data and calls create_audio_dataset(**spec, version=2609) for each spec.

  1. cache_ds: if cache_name is set and ~/data/cache_datasets/<name> exists, it is loaded from disk and processing is skipped.
  2. jsonl_dataset: reads the JSONL from az:// with blobfile and pyarrow.
  3. pre_process, run in code order:
    • input_egs_limit (take the first N)
    • path_map (rewrite the audio_path prefix)
    • rename_fields (text: display means new ← old)
    • clean_tagged_text (strip <NE>…</NE> / [tag] from text and push the inner spans to keywords)
  4. add_task_info: builds prompt, prefix, gt_output, and language.
  5. post_process: add_field (sets data_source), cache_audio, then verl_format, which emits prompt as chat, reward_model, extra_info {id, language, keywords, prefix, extra_keys…}, and data_source.

data.mix builds a deterministic stream

  • Specs are grouped by the data_source of their first row, so the two earn_fy27 specs become one source. Each mix name must exist; sources not named in the mix are silently dropped.
  • Each source is shuffled with seed 42 + group + src, then sample rows are taken. If sample exceeds the source size, the whole source repeats and the remainder is taken from the front. There is no random resampling.
  • Sources are concatenated and the group is shuffled once (shuffle: true).
  • Top-level data.shuffle: false is required with mix (otherwise it raises). It produces a SequentialSampler.
  • The mix is built once, so sample is a count for the whole dataset, not per epoch. Epoch 2 replays the same order.
  • data_source names are also the keys of reward_function_by_data_source, so a typo in either place breaks routing.

Audio → model inputs (lazy, in __getitem__)

The audio path goes through localize_audio_source, which maps az:// to $VERL_AUDIO_CACHE_ROOT (default ~/data) and downloads under a lock. load_audio handles ;-joined sources, file:count:idx chunks (chunk_load_mode: indexed reads one sample by byte offset), file#s:e slices, and zip members. limit_audio resamples to 16 kHz, pads clips under 0.16 s, and truncates to 40 s. The chat template is applied, then processor(text, audios) produces input_ids and multi_modal_inputs, and multi_modal_data={"audio":[(wav,16000)]} is passed to vLLM. Prompts are left-padded to 1024. If a load fails in training, it retries up to 8 times at other indices.

05

Reward: each sample is compared with the greedy hypothesis, measure by measure

The train reward manager is dapo. It calls the dispatcher once per sample with (data_source, solution_str, ground_truth, extra_info) and puts the score on the last response token. The dispatcher looks up reward_function_by_data_source[data_source], which names an entry in reward_functions, which points to recipe/phimm/reward/asr_vote.py:compute_score with its reward_kwargs bound. The fn's other keys become reward_extra_info for logging.

verl/trainer/ppo/reward.py:105-153 · verl/workers/reward_manager/dapo.py:71-140

Measures (all accuracies, 1 = perfect)

Parsing: get_hyp_text splits on <src=X><tgt=Y> segments and strips markup such as <VERBATIM> and <nonspeech>. Both sides are text-normalized for the language, then aligned with difflib.

char1 − CER (whitespace removed)
word1 − WER
word_del1 − deletions / n_ref
word_ins1 − insertions / n_ref (can go negative)
word_kw1 − keyword errors / n_ref; 1.0 if there are no keywords
langAlignment accuracy of the predicted src/tgt language tags
fmtFraction of well-formed segments (empty output = 0)

Per measure (compute_measure_vote, asr_vote.py:54-97):

  • delta: abs → Δ = value − greedy_value
  • vote: delta → vote = Δ (the improvement over greedy)
  • vote: abs → vote = the absolute value, ignoring greedy
  • Then vote = clip(vote, -2, 2), score = beta × vote
  • reduce: {mode: average, total: T} → Σ scores / T. This divides by T, not by the number of measures or the sum of betas.

Keywords for word_kw come from extra_info.keywords, which is filled by clean_tagged_text from NE/PName tags in the earnings and Quartr transcripts.

# librispeech (noisy_ls, earn_fy27, quartr_*) T = 2 r = [ Δchar + Δword + 0.2·Δword_del + 0.1·Δword_ins + 0.2·Δword_kw + 0.05·lang + 0.05·fmt ] / 2 # aishell1_char (aishell1_train_top10k) T = 1 r = Δchar + 0.05·lang + 0.05·fmt # Δx = clip(x_sample − x_greedy, −2, 2); lang/fmt are absolute (vote: abs)

Source:

Two consequences. (1) A sample that matches greedy exactly still gets 0.05·lang + 0.05·fmt: about +0.05 for English and +0.10 for AISHELL. Every response gets this constant bonus, and nothing subtracts it later. (2) Because of the different T and measure sets, one point of character accuracy is worth 0.5 for English and 1.0 for AISHELL, so AISHELL advantages are on a larger scale.

Advantage & actor loss

ReMax advantage

returns = reverse_cumsum(r · mask) # = r at every token advantages = returns − reward_baselines · mask advantages *= adv_scale[data_source] # all 1.0

The greedy batch is scored by the same reward_fn. When that happens, extra_info.greedy_reward is not set yet, so asr_vote returns score = 0 for every greedy row (asr_vote.py:211-213). Therefore reward_baselines = 0 and A = r. The comparison with greedy already happened inside the reward, measure by measure.

Policy + KL loss (one mini-batch, one epoch)

ratio = exp(logπθ − logπ_old) # π_old = vLLM log-probs L_pg = max(−A·ratio, −A·clip(ratio, 0.8, 1.28)) L_pg = A<0 ? min(L_pg, −A·3.0) : L_pg # dual-clip L_pg *= min(exp(logπ_old − logπ_vllm), 5) # TIS ≡ 1 here kl = exp(ref−logπθ) − (ref−logπθ) − 1 # k3, clamp ±10 loss = agg(L_pg) + 0.001 · agg(kl) agg = mean_seqs( Σ_tokens · mask ) # seq-mean-token-sum

core_algos.py:1320-1395 · 1233 agg_loss · 1839 low_var_kl · verl/workers/actor/dp_actor.py:390-501

With seq-mean-token-sum, the per-sequence loss is a sum over tokens. Because every token gets the same advantage, a 300-token response pushes about 10× harder than a 30-token one. Long earnings segments therefore dominate the gradient compared with short AISHELL utterances.

Validation & checkpointing

_validate() runs before training, every 20 steps, and at the last step. Each val spec gets its own RLHFDataset and dataloader (no mix, batch 256; val_batch_size: -1 means one batch for the whole spec). Generation is greedy (val_kwargs, max 512 tokens). Scoring uses the long_audio_grouped manager: it groups rows by (data_source, parent audio), sorts by seg_start, joins the segment hypotheses, and scores the parent once against its full reference. Rows with no parent key are scored on their own. Metrics are logged as val-core/<data_source>/… and generations are dumped to validation_data_dir, split per data source.

08

Things worth knowing

Greedy baseline costs one extra generation
Each step generates 128 greedy and 1024 sampled responses (timer gen_max). The greedy pass uses val_kwargs with response length 512, while samples get 768. A very long greedy hypothesis can be truncated and lose word/char accuracy, which inflates Δ for the samples.
The baseline lives inside the reward, not in reward_baselines
reward_baselines is always 0. If you change the reward function so it scores the greedy rows (nonzero), the comparison with greedy would be applied twice.
lang/fmt are a constant bonus
With vote: abs, every well-formed sample gets +0.05 (EN) or +0.10 (ZH) advantage. With no group mean subtracted, this slightly raises the likelihood of all well-formed responses.
TIS and entropy
π_old = π_vllm, so the TIS weight is exactly 1, and the PPO ratio measures the mismatch between the training engine and vLLM. Skipping the actor's old-log-prob pass also means actor/entropy is not logged.
Fixed data order
Mix plus SequentialSampler means runs with the same YAML see identical batches, and epoch 2 replays epoch 1's order exactly. Changing any sample count reshuffles everything.
AISHELL is ranked "hard first"
input_egs_limit: 10000 keeps the 10k highest-n_err rows of the top-20k list. The mix shuffle then spreads them through training. The prefix is cut before the shuffle.
Sources not named in the mix are dropped silently
If you add a train_data entry and forget its mix line, it is loaded and processed but never trained on, with no error.
Reward map merges, val map replaces
reward_function_by_data_source is a normal dict, so base3a's entries are merged with base1's (noisy_ls keeps librispeech). _val_reward_sources is redefined at each layer on purpose; see the comment in base1_smts.
