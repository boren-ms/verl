# hc_clean_v0 pname data

Use the released training split (7,261 utterances, 8,609 target occurrences)
and the entity-matched test as validation (7,533 utterances, 20,829 target
occurrences). Both contain 5,793 distinct target wordings. The prepared data
and configs contain these two splits only.

Prepared Orange root:

```text
az://orngwus2cresco/data/speech/pname/hc_clean_v0/
```

`train.jsonl` and `val_entity_matched.jsonl` use `text = display` exactly, in
the released order. `keywords` contains unique annotated surface forms joined
by exact ID, rather than the historical source keywords. Historical hypotheses,
WER, and names are excluded from the prepared rows. Prompts request English
verbatim transcription and do not include entity lists or reference text.

Audio is stored as original WAV bytes in uncompressed ZIP shards. Each
`audio_path` uses the existing `archive.zip!byte_offset:byte_length` loader.
`source_audio_path` and `wav_sha256` retain the original locator and released
WAV digest. `preparation.json` records counts/durations; `SHA256SUMS.json`
pins every generated manifest and shard. All selected WAVs are checked against
the published SHA-256 and native record framing during preparation.

Add the data-only bundle **after** an experiment's base defaults:

```yaml
defaults:
  - /v2611_dev/base@_global_
  - /data/pname/hc_clean_v0@_global_
  - _self_
```

The bundle selects both configs, sets a 7,261-row training mix, disables audio
truncation with `data.max_audio_dur: null`, and maps the new data sources to
the existing training and English validation scorers. Choose model, batch size,
epochs/steps and token budgets in the experiment recipe. No experiment is
launched by preparing these data.

The entity-matched test is a seen-vocabulary benchmark. As documented by the
publisher, it shares 148 parent-recording rows with training, and ten test rows
are flagged by the broader normalized whole-text overlap check. Keep it held
out: do not use test references, target annotations, or entity lists as model
inputs or as training examples. The original release contains an alternate
strict test; it is not selected or generated by this preparation.

The existing keyword reward counts lexical matches. It does **not** implement
the release's occurrence-specific entity scoring. For release EER, use the
byte-identical `targets/val_entity_matched_targets.jsonl`, join hypotheses by exact ID, and score each
annotated span once against judged `display` (the prepared `text`). The entity denominator is 20,829.
Whole-utterance validation metrics on this entity-matched test should retain
that split label and the overlap caveat.

The unmodified release, including its README, sidecars and verification tools,
is mirrored at:

```text
az://orngwus2cresco/data/speech/users/majin1/ASREvaluations/en-US/boren10k_fast2609_entity_train_test_v1/
```

Rebuild locally with an existing approved Python environment containing
`azure-storage-blob` and `soundfile`, after downloading and verifying the
release with azcopy and refreshing the source SAS using `transfer-to-orange`:

```bash
python plugins/phimm/scripts/prepare_hc_clean_v0.py \
  --release-dir /path/to/verified-release \
  --output-dir /path/to/prepared \
  --audio-cache /path/to/wav-cache \
  --orange-prefix az://orngwus2cresco/data/speech/pname/hc_clean_v0
```

Publish generated files with azcopy through `orngtransfer/data/speech/pname/`
and then to the matching Orange prefix. Existing cached WAVs are hash checked
on rebuild; no source credentials are written into the outputs.
