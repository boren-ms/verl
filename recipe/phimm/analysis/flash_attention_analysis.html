基础

一、背景：标准 Attention 的瓶颈

🧮 自注意力公式

Attention(Q, K, V) = softmax( Q KT / √dk ) · V

Transformer 的核心是自注意力（Self-Attention），其中 Q、K、V 分别为 Query、Key、Value 矩阵，dk 为 head dimension。

⚠️ 两大致命瓶颈

瓶颈说明影响
时间复杂度O(N²)，N 为序列长度序列越长，计算时间暴增
内存复杂度O(N²)，需要存储完整 N×N 注意力矩阵长序列直接 OOM
关键洞察：问题不在于计算量本身，而在于 GPU 内存层次结构。GPU 有高速但容量小的 SRAM（片上缓存，~20MB），和大容量但低速的 HBM（高带宽显存，40-80GB）。标准 Attention 需要反复在 HBM 和 SRAM 之间搬运巨大的中间矩阵 S = QKT，IO 成为性能瓶颈。

🏗️ GPU 内存层级

┌─────────────────────────────────────────┐
│ SRAM (片上缓存) ~20 MB ⚡ 极快 │
│ ─────────── 带宽瓶颈 ────────────────── │
│ HBM (显存) 40-80 GB 🐢 相对慢 │
└─────────────────────────────────────────┘
标准 Attention: Q,K → S(N×N) 写入 HBM → 读回 → softmax → 写回 → ...
Flash Attention: 分块在 SRAM 内完成，避免 N×N 矩阵写入 HBM

V1

二、FlashAttention V1（2022.05）

📝 论文信息

标题FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness
作者Tri Dao, Daniel Y. Fu, Stefano Ermon, Atri Rudra, Christopher Ré
发表NeurIPS 2022
链接arXiv:2205.14135

🎯 核心创新：IO 感知的分块计算（Tiling）

  1. 分块加载：将 Q、K、V 切分成小块，从 HBM 加载到 SRAM
  2. 块内计算：在 SRAM 中完成该块对应的 attention 计算
  3. 增量更新输出：利用 Online Softmax 技术，在不需要完整注意力矩阵的情况下正确计算 softmax
  4. 反向传播重计算（Recomputation）：前向不存储中间注意力矩阵，反向传播时重新计算——用计算换内存

🔑 关键技术：Online Softmax

标准 softmax 需要遍历整行获得最大值和求和。FlashAttention 采用递增式更新：

  • 维护每个 block 的 running maximum m 和 running sum l
  • 每处理一个新 block，用 rescaling 修正之前 block 的贡献
  • 最终得到数学上精确（exact）的结果——不是近似！
// 对于每个新 block j:
m_new = max(m_old, rowmax(S_j))
l_new = exp(m_old - m_new) * l_old + rowsum(exp(S_j - m_new))
O_new = exp(m_old - m_new) * O_old + exp(S_j - m_new) @ V_j
// 最终: O = O / l

⚠️ V1 的局限

  • GPU 利用率仅 25-40%，远低于 GEMM 的效率
  • Thread block 之间和 warp 之间的工作分配不合理，导致 occupancy 低
  • 存在不必要的 shared memory 读写

三、FlashAttention V2（2023.07）

📝 论文信息

标题FlashAttention-2: Faster Attention with Better Parallelism and Work Partitioning
作者Tri Dao
发表ICLR 2024
链接arXiv:2307.08691

🎯 核心创新：完全重写，并行性与工作分配优化

V2 是对 V1 的完全重写（Complete Rewrite），核心改进三个方面：

  1. 减少非 Matmul FLOPs
    重新调整算法，减少 rescaling 操作中的非 matmul 运算，让更多时间花在 GPU 擅长的 GEMM 上
  2. 跨 Thread Block 并行化
    V1 中一个 head 只在一个 thread block 内完成。V2 将单个 attention head 的计算分布到多个 thread block，显著提高 occupancy
  3. Warp 级别工作分配优化
    重新设计 warp 之间的工作分配，减少通过 shared memory 的通信，避免不必要的 shared memory 读写

📦 增量更新版本

v2.1

Causal Mask 对齐变更

Causal mask 从左上角对齐改为右下角对齐，与 KV cache 推理更自然配合

v2.2

推理优化

Query 序列长度很短时（如=1），将 KV cache 加载拆分到多个 thread block 并合并结果。新增 flash_attn_with_kvcache 接口

v2.3

滑动窗口注意力

Sliding Window / Local Attention，用于 Mistral 7B 等模型

v2.4

ALiBi + 确定性反向传播

支持 ALiBi（线性偏置注意力）；实现确定性反向传播模式

v2.5

Paged KV Cache

支持 PagedAttention，用于高效推理内存管理

v2.6

Softcapping

支持 attention softcapping，用于 Gemma-2、Grok 等模型

v2.7

torch.compile 兼容

支持 PyTorch 的 torch.compile 编译优化

四、FlashAttention V3（2024.07）

📝 论文信息

标题FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision
作者Jay Shah, Ganesh Bikshandi, Ying Zhang, Vijay Thakkar, Pradeep Ramani, Tri Dao
目标硬件NVIDIA Hopper GPU (H100 / H800)
链接arXiv:2407.08608

🖥️ Hopper GPU 三大新硬件特性

特性说明优势
WGMMA Warpgroup Matrix Multiply-Accumulate 吞吐量远超 Ampere 的 mma.sync，且为异步指令
TMA Tensor Memory Accelerator 硬件自动处理 global ↔ shared memory 数据搬运，释放寄存器
FP8 低精度浮点 Tensor Core 吞吐翻倍（FP16: 989 → FP8: 1978 TFLOPS）

🎯 核心创新 1：异步重叠 GEMM 和 Softmax

关键瓶颈：H100 上 matmul 有 989 TFLOPS，但 softmax 中的指数函数只有 3.9 TFLOPS（差 256 倍！）。对于 head dim=128，指数运算可能占 matmul 50% 的时间。

(a) Warpgroup 间 Pingpong 调度

时间 →→→→→→→→→→→→→→→→→→→→→→→→→→→
WG1: [GEMM₁][GEMM₀] [softmax] [GEMM₁][GEMM₀] [softmax]
WG2: [softmax] [GEMM₁][GEMM₀] [softmax] [GEMM₁]
↑ 两个 warpgroup 交替执行，softmax 隐藏在 GEMM "阴影"中

效果：570 → 620 TFLOPs/s

(b) Warpgroup 内流水线重叠

同一个 warpgroup 内部，也将 softmax 的部分操作与 GEMM 重叠执行，代价是更高寄存器压力。

效果：620 → 640-660 TFLOPs/s

🎯 核心创新 2：Warp 特化（Warp Specialization）

Producer Warps → TMA 数据搬运（global → shared memory）
Consumer Warps → WGMMA 计算（Tensor Core 矩阵乘法）
↑ 计算和数据搬运完全重叠，互不等待

🎯 核心创新 3：FP8 + 不相干处理（Incoherent Processing）

问题：LLM 激活值中有 outlier（少量极大值），直接量化到 FP8 会引入巨大误差。

解决方案：借鉴 QuIP/QuIP# 的 Incoherent Processing：

  • 对 Q 和 K 乘以随机正交矩阵（Hadamard 变换 + 随机符号）
  • 将 outlier "扩散"到所有维度，降低量化误差
  • 复杂度仅 O(d log d)，可与 rotary embedding 融合，几乎零额外开销
  • 量化误差降低 2.6×

五、FlashAttention V4（2026.03）

📝 论文信息

标题FlashAttention-4: Algorithm and Kernel Pipelining Co-Design for Asymmetric Hardware Scaling
作者Ted Zadouri, Markus Hoehnerbach, Jay Shah, Timmy Liu, Vijay Thakkar, Tri Dao
目标硬件NVIDIA Blackwell GPU (B200)
链接Blog · Paper

💡 设计哲学：非对称硬件缩放

从 H100 到 B200，Tensor Core 吞吐从 1 → 2.25 PFLOPs (BF16)，但 SFU（指数运算单元）数量和 shared memory 带宽没有增长！

资源H100B200增长
BF16 Tensor Core1 PFLOPs2.25 PFLOPs✅ 2.25×
SFU（指数单元）16 ops/SM/cycle16 ops/SM/cycle❌ 不变
Shared Memory 带宽128 B/SM/cycle128 B/SM/cycle❌ 不变
推论：前向传播瓶颈是 指数运算（SFU），反向传播瓶颈是 Shared Memory 带宽。必须彻底重新设计流水线。

🖥️ Blackwell 新硬件特性

特性说明
TMEM Tensor Memory — 每个 SM 有 256KB 片上暂存，直接连接 Tensor Core，累加器存在 TMEM 而非寄存器
tcgen05.mma 第 5 代完全异步 Tensor Core — 最大 tile 128×256×16（Hopper 的 2 倍），单线程发射，极低寄存器压力
2-CTA MMA 两个 CTA 协作执行一个 MMA — tile 扩展到 256×256×16，减少冗余 shared memory 流量

🎯 核心创新 1：前向传播 — 新 Softmax 流水线

(a) Ping-pong Q Tile 调度

  • 每个 CTA 处理两个 Q tile（QH 和 QL），交替执行
  • 2 个 softmax warpgroup 同步协调，避免同时执行 exp 以减少 SFU 竞争
  • 专门的 correction warpgroup 负责 rescaling，从关键路径中移除

(b) 软件模拟指数函数 🔥

突破性设计：不只依赖硬件 MUFU.EX2，还用 FMA 单元做 2x 的多项式近似：

// Cody-Waite range reduction:
2^x = 2^n · 2^f (n = 整数部分, f = 小数部分)
// Horner 多项式近似 2^f:
2^f ≈ p₀ + p₁·f + p₂·f² + p₃·f³
(p₀=1.0, p₁≈0.6951, p₂≈0.2276, p₃≈0.0771)
// 部分元素走硬件 MUFU，部分走软件 FMA，可调比例

让原本空闲的 FMA 单元分担指数计算，有效提升 exp 吞吐。

(c) 条件性 Online Softmax Rescaling

Oj = ⎧ exp(mj-1 - mj) · Oj-1 + exp(Sj - mj) · Vj,   if mj - mj-1 > τ
⎩ Oj-1 + exp(Sj - mj-1) · Vj,                           otherwise

当 max 变化小时跳过 rescaling，最终仍用正确统计量归一化，结果精确。

🎯 核心创新 2：反向传播 — Shared Memory 流量优化

(a) TMEM 存储中间结果

将 PT 和 dST 直接存储在 TMEM 中，5 个 GEMM 中有 2 个操作数从 TMEM 直接供给，减少 shared memory 读写。

(b) 2-CTA 反向传播

  • 两个 CTA 协作：每个 CTA 只加载一半 operand B → shared memory 流量减半
  • 通过 DSMEM（分布式 shared memory）在 cluster 内交换 dS
  • dQ 的全局原子加操作数量减半

(c) 确定性模式

信号量锁 + memory fence 序列化 dQ 全局累加，结合 CTA swizzling 和 SPT 排序减少锁争用。达到非确定性模式的 85-90% 吞吐。

🎯 核心创新 3：调度优化

  • Causal mask 负载均衡：反转 mblock 遍历顺序 + L2-sized batch-head 分区，采用 LPT（Longest Processing Time First）调度
  • 变长序列：预处理 kernel 按最长处理时间排序 batch，缓存元数据

🎯 核心创新 4：CuTe-DSL — 全 Python 实现

  • 完全用 Python 编写（CUTLASS 的 CuTe-DSL），降至 PTX 再编译为 GPU 机器码
  • 编译速度比 C++ 模板快 20-30×
  • 保持 CuTe/CUTLASS 抽象 + PTX 逃逸接口

🔄 每代升级的核心差异（Diff 视角）

V1 → V2：并行性与工程优化

- 单 head 单 thread block，低 occupancy
+ 单 head 跨多个 thread block，高 occupancy
- Warp 间频繁 shared memory 通信
+ 优化 warp 工作分配，减少 shared memory 通信
- 较多非 matmul rescaling 操作
+ 减少非 matmul FLOPs

V2 → V3：利用 Hopper 异步硬件

- 使用 Ampere mma.sync（同步指令）
+ 使用 Hopper WGMMA（异步指令）
- GEMM 和 softmax 串行执行
+ Pingpong 调度重叠 GEMM 和 softmax
- 仅支持 FP16/BF16
+ FP8 支持 + Hadamard 不相干处理降低量化误差
- CPU 处理数据搬运索引
+ TMA 硬件自动处理，释放寄存器

V3 → V4：算法与 Kernel 协同设计

- 完全依赖硬件 MUFU.EX2 计算 exp
+ 软件 FMA 多项式近似 + 硬件 MUFU 混合计算 exp
- 每步都做 online softmax rescaling
+ 条件性 rescaling，max 变化小时跳过
- 累加器在寄存器中（高寄存器压力）
+ 累加器在 TMEM 中（低寄存器压力，深流水线）
- 单 CTA 反向传播，shared memory 流量大
+ 2-CTA 反向传播，shared memory 流量减半
- CUDA C++ 实现（编译慢）
+ CuTe-DSL Python 实现（编译快 20-30×）

七、核心结论

一句话总结

FlashAttention 的每一代升级都是
算法与硬件的协同设计（Co-Design）

版本核心认知
V1认识到 IO 才是瓶颈，而非计算量
V2优化 并行性和工作分配，榨干 A100 性能
V3利用 Hopper 的 异步特性，重叠计算和数据搬运
V4针对 Blackwell 非对称缩放，算法和 kernel 流水线联合优化
